# Improvement Agent Loop / 提示词工程优化循环

Use for workflow maintenance and prompt experiments. Do not start a new drama's creative confirmation gates.

1. Restore repository state, approved decisions, prior experiment results and unresolved failures.
2. Select one demonstrated problem. Write expected behavior, reproduction and acceptance evidence.
3. Preserve a baseline: version/hash, prompt, assets, model/entry, parameters, repeated outputs where available.
4. Check official version/entry documentation. State a falsifiable hypothesis and uncertain assumptions.
5. Change the smallest relevant factor: direction, asset, task projection, capability rule or checker.
6. Run deterministic input validation and targeted regressions. Lexical hints require interpretation.
7. Generate controlled comparisons only through an available interface, within established authorization and budget.
8. Evaluate event, identity, space/contact, performance, aesthetics, connection and usable-output cost.
9. Route the failure to the responsible stage; keep other factors fixed. Stop at the configured attempt/cost limit.
10. Accept supported improvements, revert regressions, or mark unresolved. Record the model/task boundary, evidence and next experiment.

## Honest states

- local_pass: code/input checks passed.
- draft: references or capabilities are incomplete; not submission-ready.
- not_run: no model generation occurred.
- generated: a real job/output exists.
- visually_accepted: a reviewer inspected the real artifact against criteria.
- inconclusive: output evidence does not justify adopting a rule.

Lack of API access does not block local implementation. It does prevent declaring a visual-quality gain.
Local benchmark reports must retain not_run and blank visual scores until actual trials exist.

## Suggested first sequence

Correct conflicting style rules → split version/entry capabilities → repair checker scope → author intent/evidence/states → project by task → compare actual clips.
